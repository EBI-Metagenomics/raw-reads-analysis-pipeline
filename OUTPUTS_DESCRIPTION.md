# MGnify v6 raw-reads-analysis-pipeline output documentation

This document describes the different outputs produced by the MGnify v6 raw-reads-analysis-pipeline, which analyses whole genome sequencing (WGS) raw reads to generate taxonomic and functional profiles using closed-reference databases.

The pipeline functions on a per-run/sample basis, and so the outputs directory structure is also organised on a per-run basis. Additionally, the pipeline generates top-level summary files which are aggregated from all the import runs.

In this documentation, the different contents of both per-run and top-level summary outputs will be described.

## Per-run output files

There are five general categories of results, each with their own output directory. Each successful run should have all five of these directores:

```
├── decontam-stats
├── function-summary
├── multiqc
├── qc-stats
└── taxonomy-summary
```

Since these results are per-run, many of the output files use the run ID as a prefix. For the purposes of this documentation we will use the run ID `ERZ12345`.

### `qc-stats`

The `qc-stats` directory contains output files related to the quality control (QC) steps of the pipeline performed by `fastp`. There is one possible output file `ERZ12345.fastp.json` located in the `fastp` directory. This `json` file contains summary output of the `fastp` run, including the number of reads and/or bases that were filtered for various reasons. This `json` file is also used later by `MultiQC` to generate its report files.

```
├── decontam-stats
├── function-summary
├── multiqc
├── qc-stats
│   └── fastp
│       └── ERZ12345_fastp.json
└── taxonomy-summary
```

### `decontam-stats`

The `decontam-stats` directory contains output files related to the decontamination of host reads from runs by read-mapping, performed by `bwa-mem2` for short-reads or `minimap2` for long-reads.  Additionally, phiX reads are removed from run sequenced on an Illumina platform. phiX decontamination s performed prior to host decontamination. Summary statistics are generated by `samtools stats` and placed in this directory. There are 3 possible output files (6 if phiX is also removed):
* **`ERZ12345_short_read_host_all_summary_stats.txt`**: This text file is generated by `samtools stats` and contains summary statistics for all reads prior to host decontamination, such as read counts and …
* **`ERZ12345_short_read_host_mapped_summary_stats.txt`**: This text file is generated by `samtools stats` and contains summary statistics for all reads filtered out by host decontamination.
* **`ERZ12345_short_read_host_unmapped_summary_stats.txt`**: This text file is generated by `samtools stats` and contains summary statistics for all reads that remain after host decontamination.
* *`ERZ12345_short_read_phix_(all|mapped|unmapped)_summary_stats.txt`: equivalent phiX decontamination results*
* *`ERZ12345_long_read_host_(all|mapped|unmapped)_summary_stats.txt`: equivalent long-read host decontamination results*

```
├── decontam-stats
│   ├── host
│   │   ├── ERZ12345_short_read_host_all_summary_stats.txt
│   │   ├── ERZ12345_short_read_host_mapped_summary_stats.txt
│   │   └── ERZ12345_short_read_host_unmapped_summary_stats.txt
│   └── phix
│       ├── ERZ12345_short_read_phix_all_summary_stats.txt
│       ├── ERZ12345_short_read_phix_mapped_summary_stats.txt
│       └── ERZ12345_short_read_phix_unmapped_summary_stats.txt
├── function-summary
├── multiqc
├── qc-stats
└── taxonomy-summary
```

### `multiqc`

The `multiqc` directory contains a MultiQC report (`ERZ12345_multiqc_report.html`) aggregating the QC and decontamination reports generated by:
* `fastp`
* `samtools stats`

```
├── decontam-stats
├── function-summary
├── multiqc
│   └── ERZ12345_multiqc_report.html
├── qc-stats
└── taxonomy-summary
```

### `taxonomy-summary`

The `taxonomy-summary` directory contains files related to taxonomic profiling of the run. It contains three subdirectories each corresponding to a taxonomic profiling method:
* **`mOTUs`**: generated by mOTUs3
* **`SILVA-LSU`**: generated by `infernal cmsearch` extraction of rRNA sequences followed by `mapseq` mapping to a `silva` 16S LSU reference database.
* **`SILVA-SSU`** similar to above but mapped to a 16S SSU reference database

Each subdirectory contains:
1. a standardised text file reporting read counts of each taxa
2. an interactive Krona plot
3. the raw output of the taxonomic profiling tool.

Output files:
* **`ERZ12345_mOTUs.txt`**: This text file contains a tab-separated table of read counts for each taxa detected, at various taxonomic levels. It is also the Krona text input that is used to generate the Krona HTML file.
* **`ERZ12345_mOTUs.html`**: This `html` file contains the Krona HTML file that interactively displays the distribution of the different taxonomic assignments.
* **`ERZ12345_mOTUs.out`**: This text file contains the raw mOTUs output reporting read count for each taxa detected, at various taxonomic levels, including those with `0` read count.
* **`ERZ12345_SILVA-LSU.txt`**: This text file contains a tab-separated table of read counts for each taxa detected, at various taxonomic levels. It is also the Krona text input that is used to generate the Krona HTML file.
* **`ERZ12345_ SILVA-LSU.html`**: This `html` file contains the Krona HTML file that interactively displays the distribution of the different taxonomic assignments.
* **`ERZ12345_ SILVA-LSU.mseq`**: This text file contains the raw `mapseq` output reporting read count for each taxa detected, at various taxonomic levels.
* **`ERZ12345_SILVA-SSU.txt`**: This text file contains a tab-separated table of read counts for each taxa detected, at various taxonomic levels. It is also the Krona text input that is used to generate the Krona HTML file.
* **`ERZ12345_ SILVA-SSU.html`**: This `html` file contains the Krona HTML file that interactively displays the distribution of the different taxonomic assignments.
* **`ERZ12345_ SILVA-SSU.mseq`**: This text file contains the raw `mapseq` output reporting read count for each taxa detected, at various taxonomic levels.

```
├── decontam-stats
├── function-summary
├── multiqc
├── qc-stats
└── taxonomy-summary
    ├── mOTUs
    │   ├── ERZ12345_mOTUs.txt
    │   ├── krona
    │   │   └── ERZ12345_mOTUs.html
    │   └── raw
    │       └── ERZ12345_mOTUs.out
    ├── SILVA-LSU
    │   ├── ERZ12345_SILVA-LSU.txt
    │   ├── krona
    │   │   └── ERZ12345_SILVA-LSU.html
    │   └── mapseq
    │       └── ERZ12345_SILVA-LSU.mseq
    └── SILVA-SSU
        ├── ERZ12345_SILVA-SSU.txt
        ├── krona
        │   └── ERZ12345_SILVA-SSU.html
        └── mapseq
            └── ERZ12345_SILVA-SSU.mseq
```

### `function-summary`

The `function-summary` directory contains files related to functional profiling of the run. It contains one subdirectory, `Pfam-A`, corresponding to the one functional profiling method implemented based on `hmmsearch` mapping to the `Pfam-A` reference database.

Output files:
*	**`ERZ12345_Pfam-A.txt`**: This text file contains a tab-separated table of read counts for each detected Pfam-A profile (or “function”).
*	**`ERZ12345_Pfam-A.domtbl`**: This domain-level `hmmsearch` results table contains the raw output from `hmmsearch` upon which the `ERZ12345_Pfam-A.txt` file is based. It contains mapping information (e.g. quality and location) between reads and `Pfam-A` profiles.

```
├── decontam-stats
├── function-summary
│   └── Pfam-A
│       ├── ERZ12345_Pfam-A.txt
│       └── raw
│           └── ERZ12345_Pfam-A.domtbl
├── multiqc
├── qc-stats
└── taxonomy-summary
```

## Top-level summary output files

### MultiQC

This folder contains an aggregation of all file contained in the MultiQC reports for each run. As such, it is a top-level aggregation of all MultiQC reports in the pipeline run. The interactive report is found in `multiqc_report.html`.

### Output status

#### QC failed runs

The pipeline runs some check on every input run following QC, decontamination and analysis. For any run failing one of these checks, the ID and reason for failure is added to a top-level report (`qc_failed_runs.csv`). The reasons for failure are:
* `no_reads`: if there are no reads following QC and decontamination
* `no_results`: if there are no results generated
* `missing_results`: if at least one of the results files are missing

#### QC passed runs

Similarly to `qc_failed_runs.csv`, for all runs that pass the checks, the ID and status are added to `qc_passed_runs.csv`. There is only one possible status:
* `all_results`
